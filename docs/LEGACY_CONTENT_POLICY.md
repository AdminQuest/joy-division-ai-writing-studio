# Politique de gestion des contenus legacy

## Objet

Le repo contient désormais plusieurs générations de contenus.

Cette politique fixe les règles de coexistence entre :

- contenus historiques ;
- anciens formats ;
- structures stabilisées v2.

---

# 1. Principe fondamental

Les contenus legacy ne doivent pas être supprimés brutalement.

Ils doivent être :

- conservés ;
- tracés ;
- progressivement migrés ;
- explicitement qualifiés.

---

# 2. Statut des contenus legacy

Un contenu legacy correspond à :

- ancien schéma ;
- ancien format ;
- ancienne convention ;
- structure non stabilisée.

---

# 3. Doctrine de migration

La migration doit rester :

- progressive ;
- non destructive ;
- documentée ;
- réversible autant que possible.

---

# 4. Risques principaux

Les contenus legacy produisent potentiellement :

- incohérences ;
- doublons ;
- ambiguïtés ;
- variantes concurrentes.

---

# 5. Objectif final

Le repo doit progressivement tendre vers :

- un schéma homogène ;
- une doctrine unique ;
- une stabilité documentaire durable.
