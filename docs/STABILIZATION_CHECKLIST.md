# Checklist de stabilisation du repo

## Objectif

Cette checklist sert à empêcher la dérive documentaire du système.

Le repo entre désormais dans une phase de consolidation.

La priorité n’est plus :

- l’ajout de fonctionnalités ;
- l’expansion rapide ;
- l’accumulation documentaire brute.

La priorité devient :

- stabilité ;
- cohérence ;
- maintenance ;
- robustesse.

---

# 1. Arborescence

- [ ] Les grands dossiers sont stabilisés.
- [ ] Les dossiers hybrides ont été supprimés.
- [ ] Les documents maîtres ne sont plus mélangés aux sources.

---

# 2. Nommage

- [ ] Les conventions de nommage sont figées.
- [ ] Les identifiants sont uniques.
- [ ] Les identifiants historiques sont conservés.
- [ ] Les alias sont documentés.

---

# 3. Atomes

- [ ] Tous les atomes utilisent le même schéma.
- [ ] Tous les atomes possèdent les champs obligatoires.
- [ ] Les types documentaires sont cohérents.
- [ ] Les niveaux de preuve sont renseignés.
- [ ] Les risques de surinterprétation sont renseignés.

---

# 4. Registres

- [ ] Les colonnes sont stabilisées.
- [ ] Les statuts sont harmonisés.
- [ ] Les couleurs et typologies sont homogènes.
- [ ] Les doublons ont été supprimés.

---

# 5. Diagnostics

- [ ] Les diagnostics historiographiques fonctionnent.
- [ ] Les atomes fragiles sont identifiés.
- [ ] Les mythes sont cartographiés.
- [ ] Les relations sont cohérentes.

---

# 6. Cohérence narrative

- [ ] Les répétitions sont limitées.
- [ ] Les tunnels théoriques sont identifiés.
- [ ] Les couches narratives sont équilibrées.
- [ ] La saturation mélancolique est surveillée.

---

# 7. Maintenance régulière

## Hebdomadaire

- cohérence des nouveaux atomes ;
- diagnostics ;
- liens cassés ;
- doublons.

## Mensuelle

- cohérence interchapitres ;
- équilibre narratif ;
- stabilité des concepts ;
- nettoyage documentaire.
