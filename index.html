Mode d’emploi minimal

Le portail est le point d’entrée unique du dépôt. Il donne accès au RAG Studio, aux ateliers de rédaction et aux ateliers de validation documentaire. Ces espaces restent séparés afin de distinguer clairement trois opérations : retrouver les sources, rédiger le livre, contrôler les références.

1. Ouvrir un terminal dans le dossier du dépôt

Sous Windows 11, procéder ainsi :

  1. Ouvrir l’Explorateur de fichiers.
  2. Aller dans le dossier local du dépôt, par exemple :
C:\Users\TonNom\Documents\GitHub\joy-division-ai-writing-studio
  1. Cliquer dans la barre d’adresse du dossier.
  2. Taper cmd.
  3. Appuyer sur Entrée.

Le terminal s’ouvre alors directement à la racine du dépôt. C’est depuis cet emplacement que les commandes doivent être lancées.

Si le terminal est déjà ouvert ailleurs, utiliser d’abord cd pour rejoindre le dépôt. 

cd C:\Users\TonNom\Documents\GitHub\joy-division-ai-writing-studio

2. Vérifier que l’on est bien à la racine du dépôt

Lancer :

dir

La liste affichée doit contenir notamment index.html, le dossier apps et le dossier tools. Si ces éléments n’apparaissent pas, le terminal n’est pas ouvert au bon endroit.

3. Reconstruire les exports

Lancer :

python tools/build_registers.py

Cette commande doit être exécutée avant toute session de travail, puis relancée après toute modification d’une fiche source, d’un document maître, du registre des références, du fichier des citations vérifiées ou du tableau de cohérence thématique.

4. Lancer le serveur local

Lancer :

python tools/rag_server.py

Le terminal doit rester ouvert pendant toute la session. S’il est fermé, le serveur s’arrête.

5. Ouvrir le portail dans le navigateur

Quand le serveur est lancé, ne pas ouvrir le fichier index.html directement dans l’Explorateur. Il faut ouvrir le portail par son adresse locale. 

http://127.0.0.1:8765

Si l’adresse du navigateur commence par file:///, le portail n’est pas ouvert par le serveur local. Le RAG Studio affichera alors une erreur de type NetworkError when attempting to fetch resource, car les routes /api/status et /api/search ne sont pas accessibles.

6. Ordre de travail recommandé

  1. Ouvrir un terminal à la racine du dépôt.
  2. Vérifier l’emplacement avec dir.
  3. Reconstruire les exports avec build_registers.py.
  4. Lancer le serveur avec rag_server.py.
  5. Ouvrir http://127.0.0.1:8765 dans le navigateur.
  6. Interroger les sources dans le RAG Studio.
  7. Rédiger dans l’atelier de rédaction à partir des sources retrouvées.
  8. Contrôler le texte dans l’atelier de validation : sources, citations, doublons, périmètre du chapitre.

7. Règle de contrôle

Aucun passage n’est stabilisé tant que la source n’est pas identifiable, que les citations verbatim ne sont pas vérifiées, que le chapitre d’accueil n’est pas confirmé et que le tableau de cohérence thématique n’exclut pas un doublon.
