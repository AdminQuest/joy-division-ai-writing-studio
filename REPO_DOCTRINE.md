# Doctrine du repo

## Objet

Ce document constitue la doctrine officielle du repo.

Le projet n’est plus un simple espace de stockage documentaire.

Le repo constitue désormais :

- une infrastructure documentaire ;
- un environnement éditorial ;
- un système historiographique ;
- une base relationnelle spécialisée Joy Division/post-punk.

Ce document fixe :

- l’architecture ;
- les conventions ;
- les règles documentaires ;
- les règles de stabilité.

---

# 1. Principe fondamental

Le repo doit privilégier :

```text
stabilité
cohérence
traçabilité
lisibilité
non-redondance
```

Toute nouvelle fonctionnalité doit désormais être secondaire par rapport à :

- la robustesse documentaire ;
- la cohérence des schémas ;
- la stabilité des structures.

---

# 2. Hiérarchie documentaire

Le repo distingue désormais quatre couches.

## Couche 1 — Sources

Contient :

- livres ;
- archives ;
- interviews ;
- bootlegs ;
- presse ;
- documents académiques.

Les sources ne doivent jamais être confondues avec :

- les synthèses ;
- les documents maîtres ;
- les interprétations.

---

## Couche 2 — Atomes

Les atomes constituent les unités documentaires fondamentales.

Ils doivent être :

- homogènes ;
- traçables ;
- stables ;
- réutilisables.

Les schémas atomiques doivent rester strictement compatibles.

---

## Couche 3 — Registres

Les registres servent à :

- consolider ;
- indexer ;
- cartographier ;
- superviser.

Ils ne doivent pas devenir des espaces de rédaction libre.

---

## Couche 4 — Manuscrit / éditorial

Les documents maîtres et chapitres deviennent :

- couches rédactionnelles ;
- états narratifs ;
- cartes argumentatives.

Ils ne constituent plus les sources primaires du système.

---

# 3. Règles de stabilité

## 3.1 Arborescence

Les grands dossiers doivent rester stables.

Toute modification structurelle doit être exceptionnelle.

---

## 3.2 Nommage

Les conventions de nommage doivent être figées.

Les identifiants ne doivent jamais être modifiés après stabilisation.

---

## 3.3 Schémas

Les schémas documentaires constituent le cœur du système.

Toute modification de schéma doit être :

- justifiée ;
- documentée ;
- compatible ;
- rétrocompatible autant que possible.

---

## 3.4 Redondance

Une information structurante ne doit exister qu’à un seul emplacement maître.

Le repo doit éviter :

- les doublons ;
- les variantes concurrentes ;
- les synthèses divergentes.

---

# 4. Doctrine historiographique

Le repo doit constamment distinguer :

- fait ;
- lecture ;
- mythe ;
- reconstruction ;
- mémoire ;
- interprétation.

Les risques suivants doivent être surveillés :

- téléologie ;
- prophétisation rétrospective ;
- psychologisation ;
- mythologisation ;
- surinterprétation.

---

# 5. Doctrine narrative

Le manuscrit doit maintenir un équilibre entre :

- narration ;
- matérialité ;
- analyse ;
- théorie ;
- affects.

Le système doit limiter :

- les tunnels théoriques ;
- les répétitions ;
- la saturation mélancolique.

---

# 6. Maintenance

Le repo doit faire l’objet d’une maintenance régulière.

Contrôles minimaux :

- cohérence des identifiants ;
- atomes orphelins ;
- liens cassés ;
- doublons ;
- diagnostics historiographiques ;
- stabilité des registres.

---

# 7. Principe final

Le repo doit rester :

```text
compréhensible
maintenable
évolutif
historiographiquement prudent
```

La sophistication technique ne doit jamais dégrader :

- la lisibilité ;
- la robustesse ;
- la traçabilité documentaire.
